# MU300 / ZTE U30 Air 修复补丁

本仓库公开在一台 ZTE U30 Air（`u30air`，MU300 系列）上验证过的电量灯和关机充电修复，以及 Tailscale 开机自启设置说明。验证环境为 **OpenWrt 25.12.6 / mu300-linux v2026.10.29.1 / Linux 5.4.254-gb50db5b6224c**。

内容包括修复源码、差异补丁、模拟测试、安装与回退说明和脱敏后的实测记录。完整设备恢复镜像、无线配置、密码和设备密钥保留在私有备份中。此仓库提供文件级补丁；安装方法见 [INSTALL.md](INSTALL.md)。

## 修复内容

| 功能 | 修改后的行为 |
| --- | --- |
| 电量读取 | 优先使用系统归一化的百分比，避免把厂商电量计的十分之一百分比当成百分比 |
| 电量灯颜色 | 低于 10% 为红色，10%～59% 为蓝色，60% 及以上为白色 |
| 充电提示 | 识别 `bq2560x_charger` 的充电状态；充电时呼吸、充满后常亮 |
| LED 驱动初始化 | 补充加载已有 RGB 灯和 pattern 驱动；驱动就绪后再缓存显示状态 |
| 关机插电 | 在正常网络和基带服务之前进入充电等待，只刷新电量灯 |
| 充电时按键 | 电源键长按三秒后继续正常启动；短按和 Wi-Fi 键不触发开机 |
| 充电时拔线 | 确认供电消失连续两秒后，同步文件系统并关机 |
| Tailscale | 使用现有服务的自启功能，正常开机后运行；关机充电等待时随网络服务一起等待 |

重新插电最初，Wi-Fi 和信号灯仍会短暂亮起，随后熄灭、仅保留电量灯。补丁接管之后才进入上述充电等待，未修改引导程序和内核早期点灯。

## 代码结构

- `fixes/mu300-led`、`fixes/extra-modules`：实机安装的修复后脚本，旁边的 `.patch` 文件记录改动。
- `charge-only/overlay/`：新增充电等待脚本、OpenWrt 启动服务及相对启动链接。
- `charge-only/rollback.sh`：禁用充电等待启动链接，保留脚本供检查。
- `charge-only/test_charge_mode.py`：使用临时目录和模拟硬件的主机测试。
- `charge-only/smoke_on_device.sh`：在设备 BusyBox ash 上使用模拟硬件和关机命令的测试。
- `verification/`：去掉设备身份、账户及地址后的验证摘要和相关事件日志。
- `SHA256SUMS`：本次发布文件的 SHA-256 校验清单。

充电服务 `S09mu300-charge-mode` 排在 `S09mu300-vendor` 前面，等待时阻塞后续启动队列；它使用已有 `mu300-keys -l 3000 -t 1` 的文本事件接口。原电源服务、按键程序、内核和 boot 镜像保持原实现。`POWER_ON_CHARGER=1`、正常电源键开机和 failsafe 会继续普通启动。

## 验证结果

2026-10-30 在上述设备和版本上完成：

- 17 项主机模拟行为测试、2 项设备 BusyBox ash 模拟测试通过。
- 设备 shell 语法、安装文件 SHA-256、启动顺序核验通过。
- 连续充电等待 **528 秒（8 分 48 秒）**，退出前无热点、网络或基带服务。
- 拔线后全灯熄灭并保持关机，随后按电源可正常开机。
- 充电等待中长按电源后，在同一次启动中恢复正常服务，热点可连接、可以上网；放行前后和日志采集结束的启动身份一致。
- Tailscale 在本次充电等待放行后自动启动，最终检查在线且无健康告警。

详细记录见 [verification/summary.json](verification/summary.json)。这是单台设备的验证结果，其他型号和固件版本尚未验证；未进行整机刷回恢复测试。源码与已部署版本一致，本次公开仅整理发布内容。
